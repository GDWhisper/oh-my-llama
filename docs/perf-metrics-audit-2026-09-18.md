# 推理速度指标（预处理 / 生成）口径审查与去噪实施

- 审查日期：2026-09-18
- 触发：用户实测——面板「预处理 最近 48.0 tok/s · 平均 904 tok/s」vs 日志大请求 1600–1900 t/s
- 审查方式：**真实日志逐行回放**（`%APPDATA%/OhMyLlama/logs/` 全部历史日志）+ 单测固化（非静态推断）
- 结论速览：面板读数**没有解析错误**（每个数字都能从日志精确复现），偏低源于**统计口径**——① 每批固定开销主导小样本；② 多 slot 并发按 per-slot 记账、`Σtokens/Σ时间` 把重叠墙钟算两遍。同日整体替换为**下限包络拟合**（不设门槛、不丢任何样本），门禁全绿。

---

## 一、实测与根因

### 1.1 面板读数逐项对账（`llama-server_20260918_120107.log`，27B）

| 面板显示 | 日志复现 |
|---|---|
| 预处理 最近 48.0 | 14-token 缓存命中断 291.49 ms，原始读数 48.03 |
| 预处理 平均 904 | 10193 tok / 11.27852 s（= 三样本 Σtokens/Σ时间，903.75） |
| 生成 最近 72.6 | 241-token 样本原始读数 72.57 |
| 生成 平均 52.0 | 350 tok / 6.73718 s（51.95） |
| 累计 3 次请求 | 3 条 eval 行 |

对账结论：解析层无误（含时间戳/slot 前缀、ConPTY 折断行拼接均命中）；同时确认该分支新增的 `prompt processing, progress=…` / `n_gen = …, tg = …` 行未被误命中。问题在**口径**。

### 1.2 两类系统性偏差

1. **固定开销主导小样本**：同一批请求中，10k-token prefill 报 1647 t/s，而 14-token 缓存命中段只报 48 t/s——差值集中在每批固定开销（本日志拟合约 283 ms：批启动/图构建/缓存簿记）。
2. **多 slot 并发记账重叠**：两个 slot 同一时段各自汇报 timings，覆盖同一段墙钟；`Σtokens/Σ时间` 把重叠时间算了两遍（平均 904 vs 真实 ~1650）。并发挤占、卡顿、降频**只会让请求变慢**——是方向单一（单边）的噪声。

## 二、方案取舍

- 曾评估「门槛过滤」（小样本不进统计）：**否决**——暴力门槛会让真实低于门槛的数据被忽略（如小显存设备本就走得慢）。
- 定稿：**不设门槛、不丢任何样本**，用拟合把噪声从统计中剥离。

## 三、实施：下限包络拟合（`src-tauri/src/perf.rs`）

模型 `耗时 ≈ overhead_ms + ms_per_token × tokens`（`RateModel` / `fit_model`），候选直线须同时满足：

1. 落在**所有**样本下方（单边噪声只会把点推向包络上方，不污染估计）；
2. `overhead_ms ≥ 0`、斜率有限且为正；
3. 取总残差最小者；并列取**斜率更慢**者（更保守的速度估计）。

候选集 = 过任意两点的直线 ∪ **固定开销 = 0 的边界线**（`offer_candidate` 统一按总残差比较；边界线斜率取全体样本的最小每 token 耗时，是 O = 0 时唯一不穿过样本的斜率）。边界族不可缺：生成侧每 token 成本随长度上升（实测同一会话 15.5 → 18.6 ms/token），过任意两点的直线都带负固定开销、被第 2 条否决——缺了它该类数据**没有任何估计**，卡片只能回退显示最近值（表现为「生成卡片没有最近小字」，2026-09-18 用户实测发现）。

显示口径：

- **「最近」** = 单样本净速率 `tokens / max(ms − overhead, tokens × ms_per_token)`（扣每批固定开销）；
- **「估计」** = `1000 / ms_per_token`（会话净速度；面板原「平均」更名）；
- 不变量：任何样本的显示速率 ≤ 估计；单样本上修比例**恒等于「固定开销 ÷ 该请求总时长」**——设备越慢该比例越趋近 0，慢设备照慢显示。

参数：样本窗口 128 条/类；两样本 tokens 差 < 64 不给估计（斜率会被单次抖动决定）——此时「最近」回退**原始读数**，不隐藏数据。PTY 折断拼接、前缀兼容、0-token/inf 脏值过滤沿用既有逻辑不变。

## 五、已知限制

- 若一个会话**始终**处于多 slot 并发（所有样本都被摊薄），包络斜率整体偏低 → 估计偏低。根治需按日志时间戳（`M.SS.mmm.uuu`，新版 llama.cpp 才有）重建每条请求窗口做并发去重叠——实现重、已评估搁置。
- 「估计」是**下限包络**（干净运行速度），不是含卡顿的平均；单次请求的真实状况（被挤占、降频）由「最近」如实呈现，两者配合阅读。
