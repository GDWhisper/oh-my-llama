# Release Note 模板（发布时使用）

> 本模板为发布 agent 编写 GitHub Release Note 的唯一真源。每次发布前复制本模板，填入对应版本的实际内容，经 `--notes-file` 写入草稿 Release。
> 正文**必须**包含下列三大类（哪怕某一类为空，也要保留标题并写明「无」）；**不要**放「下载」栏目（资产区会自动展示）；**不要**使用 emoji。
> 详细历史与实现机制见 `CHANGELOG.md`；Release Note 只写两个已发布版本之间**用户可见**的差异（详见 `release-guide.md` 第三节红线）。

```markdown
# Oh My Llama vX.Y.Z

本版本亮点由发布 agent 基于 CHANGELOG 手动总结。详细条目见 CHANGELOG.md。

### 新增功能
- （本版本新增的、用户可直接感知的能力；无则写「无」）

### 功能优化
- （体验 / 性能 / 交互层面的改进；无则写「无」）

### Bug 修复
- （修复的、用户可感知的缺陷；无则写「无」）

> 详细改动参考 CHANGELOG
```

## 填写要点
- 顶部那句固定文案**不要改动**，它向用户说明本页内容是人工（agent）基于 CHANGELOG 提炼的总结，而非自动生成。
- 三大类顺序固定为：新增功能 → 功能优化 → Bug 修复。
- 归类示例（来自历史发布）：按钮禁用态误显蓝底 → Bug 修复；停止按钮变红、地址文案统一、`--no-webui` 置灰 → 功能优化；可搜索模型选择器 → 新增功能。
- 内容红线：开发期误加又删、从未在正式版 UI 出现过的元素，一律剔除（用户从旧版升新版不会注意到，写了反而误导）。
